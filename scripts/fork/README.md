# Fork sync

`lennartorlando/compound-engineering-plugin` follows `EveryInc/compound-engineering-plugin` by rebasing daily. Its default branch is `personal`; the fork keeps no `main` of its own.

## Branch layout of `personal`

1. Upstream `main` history.
2. The fork's patch commits.
3. Exactly one version commit on top, generated by the sync:
   - subject `fork: build version <x>-lo.<sha7>`, where `<x>` is upstream's `package.json` version and `<sha7>` is the short sha of the commit directly below (the last fork patch);
   - trailer `Upstream-Base: <full upstream sha>`, the upstream commit the patches sit on;
   - every version field release-please maintains (all `extra-files` in `.github/release-please-config.json`, plus `.github/.release-please-manifest.json`, which `bun run release:validate` compares against) set to `<upstream value>-lo.<sha7>`.

Fork commits pushed on top of the version commit are fine: the next run drops the old version commit, keeps them, and creates a new one.

## The daily run

`.github/workflows/fork-sync.yml` runs at 05:23 UTC and on demand. `scripts/fork/sync.sh` drops the version commit, runs `git rebase --onto upstream/main <Upstream-Base>`, writes a new version commit and runs the checks. Nothing is pushed when any of these blocks:

- the old base is no longer an ancestor of upstream `main` (upstream history rewritten);
- the rebase conflicts;
- a marketplace or plugin name in the release-please manifests differs from what `personal` had;
- a check fails: `bun install --frozen-lockfile`, `bun run release:validate`, `bun run test:skill-guards`, `bun test` on each `tests/fork/*.test.ts`, `bash` on each `tests/fork/*.test.sh`.

A blockage opens one issue labeled `fork-sync`; later blocked runs comment on it. A clean run, including one with nothing to do, closes it. The push uses `--force-with-lease` on the `personal` sha the run started from, so a branch that moved during the run is never overwritten.

## Resolve a blockage

Run in a checkout of the fork:

```bash
git remote get-url upstream >/dev/null 2>&1 || git remote add upstream https://github.com/EveryInc/compound-engineering-plugin.git
git fetch origin personal
git fetch upstream main
git switch -C personal origin/personal
lease=$(git rev-parse origin/personal)
v=$(git log -1 --format=%H --grep='^fork: build version ' upstream/main..personal)
base=$(git log -1 --format='%(trailers:key=Upstream-Base,valueonly)' "$v")
git rebase --onto "$v^" "$v"            # drop the version commit, keep any commits above it
git rebase --onto upstream/main "$base" # replay the fork patches
```

If `$v` is empty (no version commit), use `base=$(git merge-base personal upstream/main)` and skip the first rebase.

Then by issue type:

- **Rebase conflict** or **upstream history rewritten**: resolve each stop, `git add <files>`, `git rebase --continue`, until the rebase finishes.
- **Name changed**: decide whether the fork follows the rename; adapt the fork patches if it does not. The next run compares names against what you push.
- **Check failed**: fix it in a new fork commit on top.

Run the checks, all green:

```bash
bun install --frozen-lockfile
bun run release:validate
bun run test:skill-guards
for f in tests/fork/*.test.ts; do bun test "$f"; done
for f in tests/fork/*.test.sh; do bash "$f"; done
```

Push without a version commit and start the sync:

```bash
git push --force-with-lease=personal:"$lease" origin personal
gh workflow run fork-sync.yml -R lennartorlando/compound-engineering-plugin
```

That run creates a new version commit on top of your result and closes the issue.

## One-time setup

- Upstream's own workflows (`ci.yml`, `release-pr.yml`, `release-preview.yml`, `pages.yml`, `acpx-canary.yml`) are disabled once in the fork with `gh workflow disable <file> -R lennartorlando/compound-engineering-plugin`. A workflow upstream adds later needs the same.
- Secret `FORK_SYNC_TOKEN`: a fine-grained personal access token for this repository only, with Contents and Workflows read and write. Only the workflow's push job sees it.
